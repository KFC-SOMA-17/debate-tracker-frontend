# SCREEN_SPEC.md

## 1. 문서 목적

- 본 문서는 MVP 범위 내 화면의 구조, 상태, 사용자 인터랙션을 정의한다.
- 기능 요구사항과 완료 기준은 `docs/product/REQUIREMENTS.md`를 source of truth로 따른다.
- 본 문서는 구현 기술보다 사용자에게 보이는 화면과 상태 전환을 우선 정의한다.

## 2. 문서 범위

- 포함
  - 메인 대시보드
  - 토론 주제 입력 모달
  - 실시간 주장 트리
  - 토론 종료 확인 모달
  - 팀별 분석
  - 개인별 분석
- 제외
  - 산출물 생성

## 3. 공통 화면 규칙

### 3.1 Header

- 모든 주요 페이지는 Header를 포함한다.
- Header는 서비스명, 현재 상태, 현재 페이지 맥락을 우선 전달해야 한다.
- `debateId`가 없는 상태에서는 토론 주제를 노출하지 않는다.
- 토론 진행 중에는 토론 주제, 진행 상태, 진행 시간, 녹음 상태를 표시한다.
- 토론 시작 버튼은 토론 시작 전 상태에서만 노출한다.
- 토론 종료 버튼은 토론 진행 중 상태에서만 노출한다.

### 3.2 Global Navigation

- Global Navigation은 `메인 대시보드`, `팀별 분석`, `개인별 분석`으로 구성한다.
- 현재 페이지는 `active` 상태로 표시한다.
- 접근할 수 없는 메뉴는 `disabled` 상태로 표시한다.
- 분석 생성 중에는 분석 페이지 진입점을 `loading` 또는 준비 중 상태로 표시할 수 있다.

### 3.3 상태 표현 원칙

- 화면 상태는 `page`, `panel`, `action` 단위로 구분해 표현한다.
- 공통 상태는 `loading`, `empty`, `error`, `disabled`, `streaming`, `completed`를 기본으로 사용한다.
- 복구 가능한 오류는 패널 또는 액션 영역에서 처리한다.
- 복구 불가능한 오류는 페이지 단위 fallback으로 처리한다.
- 사용자가 클릭한 액션에서 발생한 오류는 해당 모달, 버튼, 폼 안에서 우선 안내한다.

### 3.4 Split Layout

- 메인 대시보드의 split layout은 토론 시작 전과 토론 진행 중 모두 동작해야 한다.
- 사용자는 split bar를 드래그해 좌우 패널의 너비를 조절할 수 있어야 한다.
- 특정 threshold를 넘기면 한쪽 패널이 collapse될 수 있어야 한다.
- collapse 상태에서는 복귀할 수 있는 명확한 affordance를 제공해야 한다.

### 3.5 접근 조건

| 상태                     | 메인 대시보드 | 팀별 분석 | 개인별 분석 |
| ------------------------ | ------------- | --------- | ----------- |
| 토론 시작 전             | 접근 가능     | 접근 불가 | 접근 불가   |
| 토론 진행 중             | 접근 가능     | 접근 불가 | 접근 불가   |
| 토론 종료 / 분석 생성 중 | 접근 가능     | loading   | loading     |
| 분석 완료                | 접근 가능     | 접근 가능 | 접근 가능   |
| 분석 실패                | 접근 가능     | error     | error       |

## 4. 메인 대시보드

### 4.1 토론 시작 전

#### 목적

- 사용자가 토론을 시작하기 전 대기 상태를 확인하고 새 토론을 시작할 수 있게 한다.

#### 진입 조건

- 아직 생성된 토론 세션이 없다.
- `debateId`가 없다.

#### 화면 구성

- Header
  - 로고 + 서비스명
  - 현재 상태: `토론 대기 중`
  - `토론 시작` 버튼
- Global Navigation
  - `메인 대시보드` active
  - `팀별 분석`, `개인별 분석` disabled
- 본문
  - 좌측: 실시간 속기록 empty UI
  - 우측: 쟁점별 요약 empty UI
  - 두 패널은 split layout으로 구성한다.

#### 사용자 액션

- `토론 시작` 버튼 클릭
  - 토론 주제 입력 모달을 연다.
- split bar drag
  - 패널 너비를 조절한다.
  - threshold를 넘기면 한쪽 패널을 collapse할 수 있다.

#### 상태 규칙

- 실시간 속기록은 empty 상태를 표시한다.
- 쟁점별 요약은 empty 상태를 표시한다.
- STT 연결 및 쟁점 요약 구독은 시작하지 않는다.

### 4.2 토론 주제 입력 모달

#### 목적

- 최소 입력만으로 새 토론 세션을 생성한다.

#### 트리거

- 토론 시작 전 메인 대시보드에서 `토론 시작` 버튼 클릭

#### 화면 구성

- 모달 제목: `새 토론 시작`
- 입력 필드
  - `토론 주제`
- 버튼
  - `취소`
  - `시작하기`

#### 상태 규칙

- 입력 전
  - `시작하기` 버튼은 disabled 상태다.
- 요청 중
  - `시작하기` 버튼은 loading 상태다.
  - 중복 요청은 허용하지 않는다.
- 요청 성공
  - 모달이 닫힌다.
  - 세션이 생성된다.
  - 메인 대시보드는 토론 진행 중 상태로 전환된다.
- 요청 실패
  - 모달 내부에 오류 메시지를 표시한다.

#### 사용자 액션

- 토론 주제 입력
  - 비어 있지 않은 경우에만 `시작하기`가 가능하다.
- `취소` 클릭
  - 모달을 닫는다.
- `시작하기` 클릭
  - 세션 생성 요청을 보낸다.

### 4.3 토론 진행 중

#### 목적

- 사용자가 실시간 발화와 쟁점 요약을 동시에 보며 토론 흐름을 따라갈 수 있게 한다.

#### 진입 조건

- 토론 세션이 생성되었고, 토론이 종료되지 않았다.

#### 화면 구성

- Header
  - 토론 주제
  - 현재 상태: `토론 진행 중`
  - 진행 시간
  - 녹음 상태
  - `토론 종료` 버튼
- Global Navigation
  - `메인 대시보드` active
  - `팀별 분석`, `개인별 분석` disabled
- 본문
  - 좌측: 실시간 속기록 패널
  - 우측: 쟁점별 요약 패널
- Floating Action
  - `실시간 주장 트리` 버튼

#### 실시간 속기록 패널

- 발화 카드를 시간순으로 표시한다.
- 각 발화 카드는 다음 정보를 포함한다.
  - 발화 시작 시각
  - 화자 라벨
  - 발화 내용
- 화자 라벨은 `팀 + 순번` 형식을 기본으로 한다.
  - 예: `찬성 1`, `반대 1`
- 현재 생성 중인 발화는 `streaming` 상태로 구분해 표시한다.

#### 쟁점별 요약 패널

- 상단에 쟁점 탭을 제공한다.
- 선택된 쟁점의 찬성 측 주장과 반대 측 주장을 비교 형태로 보여준다.
- 세부 근거는 accordion으로 제공한다.
- 근거 유형이 있으면 badge로 표시한다.
  - 예: 통계, 사례, 인용

#### 사용자 액션

- split bar drag
  - 두 패널의 너비를 조절한다.
- 패널 collapse / restore
  - 한쪽 패널을 접거나 다시 연다.
- 쟁점 탭 클릭
  - 선택된 쟁점 내용으로 전환한다.
- 근거 accordion 클릭
  - 근거를 펼치거나 접는다.
- `실시간 주장 트리` 버튼 클릭
  - 주장 트리 모달을 연다.
- `토론 종료` 버튼 클릭
  - 종료 확인 모달을 연다.

#### 상태 규칙

- 실시간 속기록 패널
  - 연결 전
  - 연결 중
  - 연결 실패
  - 재연결 중
  - 발화 없음
  - streaming 중
- 쟁점별 요약 패널
  - 생성 중
  - 요약 없음
  - 생성 실패
- split layout
  - 기본 분할
  - 좌측 패널 collapse
  - 우측 패널 collapse

#### 가드레일

- 메인 대시보드에는 우세 판정, 승패, 점수, 승리 확률을 표시하지 않는다.
- 메인 대시보드는 객관적인 기록과 구조화된 정보 제공에 집중한다.

### 4.4 토론 종료 후 메인 대시보드

#### 목적

- 토론 종료 이후에도 메인 대시보드를 조회용 화면으로 유지하고, 분석 생성 상태를 전달한다.

#### 진입 조건

- 토론 종료 요청이 성공했다.

#### 화면 구성

- Header
  - 토론 주제
  - 현재 상태: `토론 종료` 또는 `분석 생성 중`
- Global Navigation
  - `메인 대시보드` active
  - `팀별 분석`, `개인별 분석`은 생성 상태에 따라 loading 또는 접근 가능 상태로 전환된다.
- 본문
  - 마지막으로 확정된 실시간 속기록
  - 마지막으로 생성된 쟁점별 요약

#### 상태 규칙

- 실시간 수신은 중단된다.
- 메인 대시보드는 읽기 전용으로 유지한다.
- 분석 생성이 진행 중일 수 있음을 명확히 안내한다.

### 4.5 실시간 주장 트리

> Sprint 2 범위

#### 목적

- 현재까지의 토론 내용을 주제, 주장, 근거 관계로 시각화한다.

#### 트리거

- 메인 대시보드의 `실시간 주장 트리` 버튼 클릭

#### 화면 구성

- 전체 화면 모달
- 중앙 마인드맵 영역
  - 노드
  - 엣지
  - zoom control
- 우측 상세 패널
  - 기본 상태는 닫힘
  - 노드 선택 시 열림

#### 사용자 액션

- 배경 drag
  - pan 이동
- 마우스 휠 또는 컨트롤
  - zoom in / zoom out
- 노드 drag
  - 노드 위치 이동
- 노드 hover
  - 관련 노드와 엣지를 강조한다.
- 노드 click
  - 우측 상세 패널을 연다.
- 닫기 버튼 클릭
  - 상세 패널 또는 모달을 닫는다.

#### 상태 규칙

- 모달 닫힘 / 열림
- 노드 hover
- 노드 selected
- 상세 패널 열림 / 닫힘
- 데이터 없음
- 노드 생성 중

### 4.6 토론 종료 확인 모달

#### 목적

- 사용자의 실수로 토론이 종료되지 않도록 한 번 더 확인한다.
- 종료 후 분석이 생성된다는 점을 안내한다.

#### 트리거

- 토론 진행 중 Header의 `토론 종료` 버튼 클릭

#### 화면 구성

- 모달 제목: `정말 종료하시겠습니까?`
- 안내 문구
  - 종료 후 토론 발화 내용을 기반으로 분석이 생성됩니다.
  - 분석 생성에는 다소 시간이 소요될 수 있습니다.
- 버튼
  - `취소`
  - `종료`

#### 상태 규칙

- 요청 전
  - 확인 모달이 열린 상태다.
- 요청 중
  - `종료` 버튼은 loading 상태다.
- 요청 성공
  - 모달이 닫힌다.
  - 실시간 수신이 중단된다.
  - 메인 대시보드는 종료 후 상태로 전환된다.
- 요청 실패
  - toast 또는 액션 오류 메시지로 실패를 안내한다.

#### 사용자 액션

- `취소` 클릭
  - 모달을 닫고 토론 진행 상태를 유지한다.
- `종료` 클릭
  - 토론 종료 요청을 보낸다.

## 5. 팀별 분석

### 5.1 목적

- 토론 종료 후 팀 단위 분석 결과를 서술형 중심으로 제공한다.

### 5.2 진입 조건

- 토론이 종료되었다.
- 팀별 분석 데이터가 생성 중이거나 완료되었다.

### 5.3 화면 구성

- Header
  - 현재 상태: `분석 생성 중`, `분석 완료`, `분석 실패` 중 하나
- Global Navigation
  - `팀별 분석` active
- 본문
  - 페이지 제목: `팀별 분석`
  - 팀별 종합 설득력 점수
  - 팀별 총평
  - 잘한 점
  - 아쉬운 점
  - 쟁점별 우세 판정
  - 관련 발화 확인 진입점

### 5.4 사용자 액션

- 쟁점별 피드백 확인
- 관련 발화 보기 클릭
  - 해당 판정과 연결된 원문 발화를 확인한다.

### 5.5 상태 규칙

- 분석 생성 중
  - loading 화면 또는 skeleton을 표시한다.
- 분석 완료
  - 리포트 본문을 표시한다.
- 분석 실패
  - 오류 메시지와 재시도 안내를 표시한다.
- 관련 발화 없음
  - 관련 발화 영역에 empty 상태를 표시한다.

### 5.6 가드레일

- 점수는 보조 지표로만 사용한다.
- 우세 판정은 숫자 비교보다 서술형 설명을 우선한다.

## 6. 개인별 분석

### 6.1 목적

- 토론 종료 후 발화자별 피드백을 개인 복기 중심으로 제공한다.

### 6.2 진입 조건

- 토론이 종료되었다.
- 개인별 분석 데이터가 생성 중이거나 완료되었다.

### 6.3 화면 구성

- Header
  - 현재 상태: `분석 생성 중`, `분석 완료`, `분석 실패` 중 하나
- Global Navigation
  - `개인별 분석` active
- 본문
  - 페이지 제목: `개인별 분석`
  - 발화자 탭
  - 개인 종합 평가
  - 개인 발언별 피드백 카드
  - `PDF 리포트 발행` 버튼

### 6.4 발화자 탭 규칙

- 발화자 탭은 `팀 + 순번` 형식을 기본으로 한다.
  - 예: `찬성 1`, `반대 1`
- 현재 선택된 발화자는 active 상태로 표시한다.
- 탭은 순위나 랭킹처럼 보이지 않게 구성한다.

### 6.5 사용자 액션

- 발화자 탭 클릭
  - 선택된 발화자의 리포트로 전환한다.
- 발언별 피드백 확인
- `PDF 리포트 발행` 버튼 클릭
  - 선택된 발화자의 PDF 생성 또는 다운로드를 시작한다.

### 6.6 상태 규칙

- 분석 생성 중
  - loading 화면 또는 skeleton을 표시한다.
- 분석 완료
  - 선택된 발화자의 리포트를 표시한다.
- 선택 발화자 변경
  - 해당 발화자의 내용으로 즉시 전환한다.
- 선택된 발화자의 데이터 없음
  - empty 상태를 표시한다.
- PDF 생성 중
  - 버튼은 loading 상태다.
- PDF 생성 실패
  - 오류 메시지를 표시한다.
- PDF 생성 완료
  - 다운로드 또는 완료 상태를 표시한다.

### 6.7 가드레일

- 개인 피드백은 점수보다 서술형 개선 방향을 우선한다.
- 공개 랭킹 또는 경쟁형 표현은 사용하지 않는다.
