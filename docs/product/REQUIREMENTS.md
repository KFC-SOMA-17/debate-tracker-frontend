# REQUIREMENTS

디베이트 트래커 프론트엔드의 제품 요구사항을 한 문서로 요약한다. 상세 SRS와 화면 명세를 통합해, "이 앱이 무엇을 하고 / 어떤 화면이 있고 / 어떻게 흐르는가"에 집중한다.

> 이 프론트엔드는 백엔드 개발자가 토론 분석 서비스를 실험·탐구하기 위한 최소 장치다. 픽셀 단위 디자인, 고성능 최적화, 촘촘한 예외 처리는 목표가 아니다.

## 1. 제품 개요

- 토론을 실시간으로 기록(STT)하고, 발화를 쟁점·주장·근거 구조로 정리하며, 토론 종료 후 팀별/개인별 분석을 제공하는 웹 서비스다.
- 핵심 흐름: `랜딩 → 토론 준비 → 세션 워크스페이스(실시간 속기록 + 쟁점 요약) → 토론 종료 → 사후 분석`.
- MVP는 데스크톱 웹(최신 Chrome) 기준. 모바일 대응은 범위 밖.

## 2. 화면 레이어와 URL

| 레이어 | URL | 설명 |
| --- | --- | --- |
| Public | `/` | 랜딩. `토론 시작` 버튼만 제공 |
| Public | `/setup` | 토론 준비. 주제 입력 + 세션 생성 |
| Session | `/debates/:debateId` | 세션 워크스페이스(메인 대시보드) |

- Public 레이어에서는 토론 주제·진행 상태·녹음 상태·Global Navigation·STT·마이크를 활성화하지 않는다.
- Session 레이어에서만 Header에 토론 주제/상태/진행시간/녹음상태/종료 버튼과 Global Navigation을 노출한다.
- 진행 중 세션이 클라이언트에 추적되면 `/`·`/setup` 진입 시 현재 세션으로 redirect할 수 있다. 새로고침 시 추적이 초기화될 수 있다(세션 복원은 MVP 비보장).

## 3. 용어집 (도메인 ↔ 코드)

| 도메인 용어 | 코드 식별자 | 의미 |
| --- | --- | --- |
| 음성 | `audio` | 마이크 입력 오디오(Web Audio/PCM 처리 계층) |
| 주제 | `topic` | 토론 주제 (STOMP 브로커 `topic`과 구분) |
| 쟁점 | `agenda` | 발화에서 추출한 논점 |
| 주장 | `claim` | 쟁점에 대한 찬성/반대 측 주장 |
| 근거 | `evidence` | 주장을 뒷받침하는 통계/사례/인용 |
| partial 발화 | `partial` | STT가 생성 중인 미확정 발화 |
| final 발화 | `final` | STT가 확정한 발화 |

## 4. 핵심 화면

### 4.1 랜딩 (`/`)
- 서비스 진입점. `토론 시작` 버튼 클릭 시 `/setup`으로 이동.

### 4.2 토론 준비 (`/setup`)
- 토론 주제 입력 폼 + `취소`/`토론 시작` 버튼.
- 주제가 비면 `토론 시작` 비활성. 요청 중 중복 제출 금지.
- 성공 시 세션 생성 후 `/debates/:debateId`로 이동, 실패 시 페이지 내 오류 표시.

### 4.3 메인 대시보드 (`/debates/:debateId`) — 토론 진행 중
- 좌우 split layout: 좌측 **실시간 속기록 패널**, 우측 **쟁점별 요약 패널**.
- split bar 드래그로 너비 조절, threshold 초과 시 한쪽 패널 collapse(복귀 affordance 제공).
- 우측 하단 `실시간 주장 트리` Floating Button (Sprint 2).
- 실시간 속기록 패널: 발화 카드(시작 시각, 화자 라벨 `찬성 1`/`반대 1`, 내용)를 시간순 표시. partial은 생성 중(streaming) 상태로 구분.
- 쟁점별 요약 패널: 상단 쟁점(agenda) 탭, 선택 쟁점의 찬/반 주장(claim) 좌우 비교, 근거(evidence)는 accordion + 유형 badge(통계/사례/인용).

### 4.4 메인 대시보드 — 토론 종료 후
- 실시간 수신 중단, 읽기 전용 유지. 마지막 확정 속기록/요약 표시. 분석 생성 중 상태 안내.

### 4.5 토론 종료 확인 모달
- `토론 종료` 클릭 시 확인 모달. 종료 시 분석이 생성됨을 안내. 요청 중 `종료` 버튼 loading, 실패 시 toast/액션 오류.

### 4.6 실시간 주장 트리 (Sprint 2)
- 전체 모달. 주제·주장·근거를 노드/엣지로 시각화. zoom/pan/drag, 노드 hover 강조, 노드 click 시 우측 상세 패널.

### 4.7 팀별 / 개인별 분석 (토론 종료 후)
- Global Navigation에서 토론 진행 중에는 `disabled`, 종료 후 생성 상태에 따라 loading → 접근 가능.
- 팀별: 종합 설득력 점수(보조 지표), 총평, 잘한 점/아쉬운 점, 쟁점별 우세 판정(서술형 우선), 관련 발화 진입점.
- 개인별: 발화자 탭(`찬성 1`/`반대 1`), 종합 평가(서술형), 발언별 피드백 카드, PDF 리포트 추출.

## 5. 실시간 데이터 규칙

- STT `partial`/`final`을 구분한다. 같은 발화의 partial은 갱신, final 수신 시 확정 목록으로 전환, partial/final 중복 표시 금지.
- 중복 이벤트·지연 도착·재연결을 고려한다. 발화는 시작 시각 또는 서버 sequence 기준 정렬.
- 쟁점 요약은 발화 누적에 따라 주기적으로 갱신(현재 폴링). 갱신 중 선택 쟁점 유지, UI 과도한 흔들림 방지.
- 연결 상태(연결 전/중/실패/재연결/수신)를 UI로 표시한다. WebSocket/STOMP 문제는 Suspense가 아닌 연결 상태 UI로 처리.

## 6. 상태 표현 / 가드레일

- 화면 상태는 `page` / `panel` / `action` 단위로 구분. 공통 상태: `loading`, `empty`, `error`, `disabled`, `streaming`, `completed`.
- 복구 가능한 오류는 패널/액션 영역에서, 복구 불가 오류는 페이지 단위 fallback으로 처리한다.
- 메인 대시보드에는 우세 판정·점수·승리 확률 등 주관 판단 정보를 표시하지 않는다. 객관적 기록과 구조화 정보에 집중.
- 개인별 분석은 공개 순위/랭킹을 제공하지 않는다. 피드백은 점수보다 서술형 개선 방향 우선.

## 7. 범위

- In Scope: 진입 플로우, 실시간 속기록, 쟁점 요약, split layout, 주장 트리, 팀별/개인별 분석.
- Out of Scope(MVP): 모바일 최적화, 계정/권한 고도화, 실시간 승리 확률, 논리적 오류 탐지 고도화.
- Deferred: 분석 기반 산출물 생성(카드뉴스, 세특 참고 초안) — 후속 Sprint.

## 8. 현재 구현 상태

- Sprint 1 범위(진입 플로우, 실시간 속기록, 쟁점 요약, split layout, 토론 시작/종료) 중심으로 구현.
- 백엔드 API 미연동 구간은 mock(MSW)으로 대체 가능하며, 실제 API/STOMP로 교체하기 쉬운 구조를 유지한다.
- 데이터·Socket 이벤트의 최종 스펙은 백엔드 API 명세 확정 시 보완한다.
